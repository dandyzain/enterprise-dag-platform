## ⚡ Key Highlights & Core Capabilities

### 1. Mathematical Graph Orchestration (DAG)
* **Kahn's Algorithm & Topological Batching:** Decomposes complex node dependencies into execution tiers. Nodes in the same tier can be processed concurrently while strictly honoring upstream prerequisites.
* **DFS 3-Color Cycle Detection:** Before any workflow is saved or published, a white/gray/black Depth-First Search traverses the graph. Any cyclic loop is rejected with the exact path traced (e.g. `A → B → C → A`).
* **Hierarchical Auto-Layout:** One-click visual layout optimization using topological rank sorting.

### 2. Cascading Variable Interpolation
Interpolates dynamic context across steps using standard mustache syntax:
* `{{trigger.body.property}}`: Data from inbound Webhooks or manual trigger payloads.
* `{{steps.node_id.output.data.field}}`: Context output generated by upstream action nodes.
* `{{credentials.SECRET_NAME}}`: Decrypted tokens retrieved directly from the hardware-grade vault.

### 3. Security Model
* **Server-side authorization everywhere:** every page, server action and API route verifies the signed session and the caller's role (`OWNER` / `ADMIN` / `MEMBER` / `VIEWER`) — RBAC is not just hidden buttons.
* **Tenant isolation:** workflows, runs, credentials, members and audit logs are scoped to the active workspace; ids from other workspaces behave as "not found".
* **Sessions:** HMAC-SHA256 tokens with expiry, re-validated against the user store on every request (role changes and removals apply immediately); password change and "sign out everywhere" revoke older tokens. `SESSION_SECRET` is mandatory in production.
* **Credential vault (AES-256-GCM):** unique 96-bit IV per record, GCM auth tags, workspace-scoped, rotatable; decrypted secrets are injected at run time and **redacted** from run logs and step-test responses.
* **Anti-SSRF egress:** literal-IP checks (IPv4/IPv6, mapped, CGNAT, decimal/hex notations), **DNS answers validated at socket connect time** (defeats DNS rebinding), manual redirect following with per-hop checks, response size caps and timeouts.
* **Webhooks:** constant-time shared secrets, Stripe / GitHub / generic HMAC signature verification over the raw body, 1 MiB body limit, per-IP + per-endpoint rate limits, drafts only accept test deliveries from workspace members.
* **Headers:** CSP, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, HSTS on HTTPS deployments; login/registration attempt throttling.

### 4. Distributed Execution Engine
* Inbound webhooks (`POST /api/workflows/wh/[slug]`) acknowledge with **HTTP 202 Accepted** and enqueue to **BullMQ / Redis**; a standalone worker (`pnpm worker`) executes runs.
* Steps of the same topological tier run **concurrently**; a step runs only if all parents succeeded, otherwise it is recorded as **SKIPPED**. A run is **FAILED** when any step fails (HTTP 4xx/5xx included, configurable) or the plan's time limit is hit.
* Step types: manual trigger, webhook, **schedule (cron, UTC)**, HTTP request, **transform (JSON template)**, **delay**, filter.
* Live run telemetry over SSE, fanned out across processes with Redis pub/sub (plus a polling safety net).
* Plan quotas are enforced: workflows per workspace, runs per month, run duration; execution history is pruned daily per plan retention.
* Without Redis the web process runs jobs in-process; without PostgreSQL the app falls back to a **non-durable** in-memory store (reported as `degraded` by `/api/health`, retried automatically).

### 5. Multi-Language Internationalization (i18n)
* Modular internationalization powered by `next-intl`.
* English (`en`) as canonical default with full Indonesian (`id`) localization for all interface elements, node configuration forms, validation warnings, and toasts.

### 6. Product UI ("Mission Control" design system)
* **Dark-first with a real light theme** (and system mode), Geist type, validated colour tokens — see [`docs/design-system.md`](docs/design-system.md).
* **App shell**: collapsible sidebar, `⌘K` command menu, live system status from `/api/health`, mobile bottom tab bar.
* **Dashboard** with real KPIs (runs/day sparkline, success rate, average duration), DAG thumbnails, search, filters and a template gallery for new workflows.
* **Runs**: sortable/filterable table, step-level timeline, live SSE updates and one-click *Replay in editor*.
* **Editor**: quick-add step picker, insert-on-edge, undo/redo, unsaved-changes guard, docked inspector with JSON editing and `{{` variable autocomplete, run timeline with live logs.
* **Workflow management**: duplicate, enable/disable and delete from the dashboard or the editor (type-to-confirm).
* **Team & account**: link-based invitations with roles, role changes and removal (role hierarchy enforced, last owner protected), workspace switcher, profile, password change, sign out everywhere, **audit log**.
* **Accessible & responsive**: WCAG 2.2 AA design targets, keyboard-first flows, reduced-motion support, layouts for phone, tablet and desktop.

## 🚀 Quickstart & Installation

### Option 1: Docker Compose (All-in-One Enterprise Stack)
Spin up PostgreSQL, Redis, Next.js Web App, and the Standalone BullMQ Worker with one command:
```bash
docker compose up --build -d
```
Open [http://localhost:3000](http://localhost:3000) in your browser.

---

### Option 2: Local Development Setup

#### Prerequisites
* Node.js v20+ or v22+
* pnpm v9+ or v12+

#### 1. Clone & Install Dependencies
```bash
git clone <repository_url>
cd enterprise-dag-platform
pnpm install
```

#### 2. Environment Configuration
Copy `.env.example` to `.env` and fill in the secrets:
```ini
DATABASE_URL="postgresql://dag_user:dag_password_secret_2026@localhost:5432/enterprise_dag?schema=public"
REDIS_URL="redis://localhost:6379"
SESSION_SECRET="<openssl rand -hex 32>"          # required in production
ENCRYPTION_MASTER_KEY="<openssl rand -hex 32>"   # 64 hex chars, never rotate casually
NEXT_PUBLIC_APP_URL="http://localhost:3000"
DEMO_MODE="true"                                 # public demo accounts (default: dev only)
```
See [`DEPLOYMENT.md`](DEPLOYMENT.md) for every variable (`SCHEDULER_ENABLED`, `CRON_SECRET`, `LOG_LEVEL`).

#### 3. Database Schema & Seed
```bash
pnpm prisma:generate
pnpm db:push
pnpm prisma:seed
```
*Without PostgreSQL the platform falls back to an in-memory store — fine for a quick look, but nothing survives a restart.*

**Demo accounts** (only while `DEMO_MODE` is on, all in the isolated "Acme Global Enterprise" workspace, password `Password123!`): `admin@enterprise.io` (Owner), `editor@enterprise.io` (Member), `viewer@enterprise.io` (Viewer).

#### 4. Run Development Server
```bash
pnpm dev
```
Navigate to:
- English: [http://localhost:3000/en](http://localhost:3000/en)
- Bahasa Indonesia: [http://localhost:3000/id](http://localhost:3000/id)

#### 5. Run Standalone Background Worker (Optional)
```bash
pnpm worker
```
The worker processes BullMQ jobs and runs the cron scheduler and daily retention. When it runs, set `SCHEDULER_ENABLED=false` on the web process.

## 🧪 Quality Gates

```bash
pnpm typecheck   # tsc --noEmit
pnpm lint        # ESLint (next/core-web-vitals + typescript)
pnpm test        # Vitest unit & integration suites (no server needed)
pnpm test:e2e    # HTTP smoke tests against a running server (TEST_APP_URL, default http://localhost:3000)
```

CI (`.github/workflows/ci.yml`) runs typecheck, lint, unit tests and a production build, then boots PostgreSQL + Redis, seeds, starts the web server **and** the worker, and runs the E2E smoke suite.

### Test Coverage Highlights:
- `tests/authorization.test.ts`: server actions reject anonymous/forbidden callers, tenant isolation (no cross-workspace reads/overwrites), quotas, token expiry & revocation.
- `tests/webhook-route.test.ts`: exact shared secrets, GitHub signatures on the raw body, size limits, unpublished workflows.
- `tests/execution-engine*.test.ts`: tier parallelism, AND-join skips, FAILED runs on HTTP errors, credential injection + redaction, time limits, SSRF inside workflows.
- `tests/security-*.test.ts`: SSRF bypass attempts (decimal/hex/IPv6-mapped/CGNAT/metadata hosts), redirect checks, response caps, signatures, rate limiting.
- `tests/cron.test.ts`, `tests/workspace-team.test.ts`, `tests/dag.test.ts`, `tests/crypto.test.ts`, `tests/variable-interpolation.test.ts`.

## 🔌 API Reference: Webhook Ingestion

### Ingest Inbound Webhook Event
Only **published** workflows accept external deliveries (drafts accept test deliveries from signed-in members). If the webhook step defines a shared secret, send it as `X-Webhook-Secret: <secret>` or `Authorization: Bearer <secret>`; signature verification (Stripe, GitHub, generic HMAC) is configured on the step with a vault credential.

```http
POST /api/workflows/wh/:path
Content-Type: application/json
X-Webhook-Secret: <shared secret, if configured>

{
  "customerId": "cust_9824",
  "email": "jane.doe@enterprise.io",
  "tier": "enterprise",
  "amount": 2500
}
```

#### Response:
```json
HTTP/1.1 202 Accepted
Content-Type: application/json

{
  "accepted": true,
  "status": "Accepted",
  "executionId": "exec_1729241890_x89a",
  "workflowId": "wf_customer_enrichment",
  "timestamp": 1729241890000
}
```

Errors: `400` malformed JSON / invalid path · `401` bad secret or signature · `404` unknown path · `409` workflow not published · `413` body > 1 MiB · `429` rate limit or monthly run quota.

### Other endpoints
| Endpoint | Auth | Purpose |
| :--- | :--- | :--- |
| `GET /api/health` | public | Real DB / Redis / queue checks (`healthy` or `degraded`) |
| `GET /api/workflows/:id/executions` | session (`execution:view`) | Run history of a workflow in your workspace |
| `GET /api/workflows/:id/executions/:execId/stream` | session | Live run telemetry (SSE) |
| `GET /api/cron/tick` | `Authorization: Bearer $CRON_SECRET` | One scheduler tick for serverless hosts |
